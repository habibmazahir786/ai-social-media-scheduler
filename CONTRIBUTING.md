# Contributing

Thank you for helping make this an accurate, practical, vendor-neutral resource. Contributions can include corrections, clearer examples, accessibility improvements, and links to current primary documentation.

## Before you contribute

- Read the relevant guide and check for an existing issue or pull request covering the same change.
- Prefer official platform documentation and other primary sources for claims about APIs, publishing rules, and account eligibility.
- Keep product descriptions factual, attributed, and limited to features that can be verified on the product's current website.
- Do not add credentials, private customer information, or unsupported performance claims.

## Suggest a change

For a question or proposed resource, open an issue using the [suggestions template](.github/ISSUE_TEMPLATE/suggestions.md). For a direct correction, open a pull request with a concise description of the problem and how you checked the change.

## Writing guidelines

- Use plain language and explain specialist terms on first use.
- Keep advice useful regardless of which scheduling product a reader chooses.
- Distinguish a general recommendation from a platform-specific requirement.
- Link to authoritative sources and mark time-sensitive information as such.
- Use relative links for files within this repository.
- Do not promise that automation or AI will improve reach, engagement, or sales.

## Review checklist

Before submitting, check that:

- The Markdown renders clearly and headings follow a logical order.
- Internal links point to existing files or sections.
- Factual and time-sensitive claims have an appropriate source.
- Examples protect private information and retain human review where it matters.
- The change does not repeat existing material without adding value.
